# 账户、会话与权限

首次访问必须注册；第一个账户成为管理员，之后的账户默认为 analyst。没有预置用户名、密码或自动登录。用户名 3–32 位字母/数字/下划线，密码 10–128 字符。密码使用 PBKDF2-HMAC-SHA256、310000 次迭代、每个密码随机盐；未知用户名执行等量密码验证，登录失败有限速。密码散列不会返回前端或放入共享协议库。

会话使用 32 字节安全随机令牌，数据库只存 SHA256、归属、凭据版本和 12 小时过期时间。浏览器通过 HttpOnly、SameSite=Strict 的 cookie 发送，不把令牌放在 localStorage 或响应 JSON 中。外部 HTTPS 部署设置 COOKIE_SECURE=true 与 ALLOWED_ORIGINS。开发与本地部署允许配置的 localhost/127.0.0.1 前端来源；跨来源写请求被拒绝。

| 角色 | 权限 |
|---|---|
| viewer | 读取行情、指标、自选和本人报告；管理本人资料/密码/会话 |
| analyst | viewer + 优化回测、自选和本人报告写入 |
| admin | analyst + 查看用户列表、分配角色、启用/停用账户 |

权限校验在 Scala 路由执行。隐藏按钮不是安全边界。每次请求都检查会话有效性、当前账户凭据版本、是否启用和当前角色，因此角色变化即时生效。改密提高凭据版本，使旧会话即使尚未清理也不能继续使用。管理接口保留最后一个有效管理员。

自选表主键为 (user_id,symbol)，报告的查询和删除都约束 user_id。这个 ID 由服务端验证的会话注入，客户端请求若自行提交 userId/role/identity/sessionToken 就返回 400。管理员角色也不会绕过报告与自选的个人归属。退出/切换用户清空前端当前研究状态。

账户、会话、权限分别持有自己的独立 PostgreSQL 实例。初次注册跨服务配置失败时账户记录保留，用户可重试登录完成幂等权限配置，不把已产生的远程状态假装成原子分布式事务。

旧版匿名自选/报告不会自动分配给第一个注册用户。确认归属后，使用 `APERTURE_LEGACY_DSN` 指定旧实例，执行 `python scripts/migrate-legacy-research.py --owner <existing-account-uuid>`；它仅复制、保留原数据，重跑不重复写入。旧数据目录不会被启动器删除。

本项目为本地课程研究终端：没有邮件找回密码、MFA、TLS 证书管理、实盘交易或多租户组织功能，不宣称具备券商生产系统安全能力。
