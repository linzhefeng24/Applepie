# 低内存执行入口（与原训练独立）

实现三项存储/执行改动：

1. 神经反向按20ms保存边界、重算块内状态，而不是把1400个毫秒边界全部长期保留。
2. 神经正向、物理反向、神经反向依次在单独进程执行，每阶段退出后释放完整编译和自动微分堆。
3. 阶段间只传207参数和130通道输入/梯度。Adam及正则化代码仍使用原训练入口，不另写一种优化器。

仍然模拟全部3988细胞、485045条连接、1400ms神经过程和完整0.4秒/4000步物理过程。
保留原200ms神经截断与原代理梯度、float64、所有接触/NoSlip方程、手调锚点和正则项。
没有增加截断梯度、降低精度、删神经元、缩短目标或插入目标状态。

这是新增执行适配器，原ZIP中的模型与已校验源文件不改写。神经方程仍来自原文件，只替换最后一行扫描的存储布局；源哈希必须匹配。
在原server.py上仅替换启动子进程的入口，仍复用其隔离目录、检查点恢复、计数及导出逻辑。
完整验证将比较手调起点的损失与207维梯度：基准从已保存的第一次Adam状态和梯度范数代数恢复，不声称重新跑过原始基准。

## 使用

先把低内存补充包解压到现有 `~/applepie_local`，新增 `lowmem/` 和 `run_lowmem.sh`，不覆盖原模型代码。

```bash
cd ~/applepie_local
bash run_lowmem.sh check
nohup bash run_lowmem.sh benchmark > lowmem.log 2>&1 &
tail -f lowmem.log
```

只启动一份本地计算。GitHub那一路训练不受影响。
低内存入口默认限制4个逻辑CPU，避免22线程电脑的并行编译增加内存峰值；该上限不改变模型方程。
新目录名称含 `lowmem-benchmark`，与普通测速目录区分。报告 `cache/train/low-memory-last.json` 含每阶段峰值内存、耗时，以及主进程与最大子进程峰值之和的保守上限。
它不是整个Windows系统占用；WSL内其它进程和系统开销还需要内存。

继续该低内存运行：

```bash
nohup bash run_lowmem.sh train --resume runs/实际低内存目录 > lowmem-train.log 2>&1 &
```

该方式会重复神经计算和部分编译，可能比原版更慢。不能在实测前承诺省多少GB、是否适合当前7.5GB WSL或具体耗时。
当前原物理反向的近似性与26路MN映射缺口仍存在；省内存并不提高生理真实性或消除梯度误差。
